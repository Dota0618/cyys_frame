# 数据库与 SQL

- 不建立数据库外键，表间关系和删除影响记录在模块文档。
- 按需保留主键、唯一键、非空约束和索引。
- 普通查询最多关联 3 张表；权限和统计查询的例外须检查执行计划。
- 展示字段遵循[缓存规则](cache-usage.md)，不改成逐行查询。
- 拆分查询保持分页、总数、排序和过滤结果一致。
- 输入和业务校验遵循[API 规则](api-command-validation.md)。
- 机构和操作者由服务端赋值。
- 修改和删除必须限定记录及授权范围，影响行数为 0 不默认成功。
- 默认按创建时间倒序；部门、机构和菜单按 `sort` 升序。
- 同值追加主键排序，不开放通用前端自选排序字段。
- 系统内置字典及其字典项只读，通过版本迁移维护。
- 字典写入在父分类锁内检查，管理员不得绕过内置保护。
- 新建字典为业务字典，不提供切换内置属性的接口。
- 内置分类按迁移清单维护，不按名称或前缀推断。

## 流水号

- 业务通过 `SerialNumberService.next("固定业务代码")` 取号。
- 规则使用外部 `cyys.serial-numbers.definitions` 配置，不开放通用取号接口。
- 调用方先完成业务授权，取号服务复核当前机构和对应操作权限。
- 前缀以大写字母开头，仅含大写字母、数字和下划线，以单个 `-` 结尾。
- 周期、位宽和时区由规则指定，机构和周期由服务端确定。
- 使用数据库唯一键和行锁保证取号一致，不以进程锁或缓存计数替代。
- 取号及审计独立提交，允许断号，已预留号码不复用。
- 优先在取得业务写锁前取号。
- 已使用规则不得原位修改，变更使用新业务代码和前缀。
- 序号耗尽时拒绝取号，不回零。
- 业务表保留机构与业务号码的联合唯一约束。
- 旧全局计数不得直接导入，迁移先确认归属和历史最大号。
