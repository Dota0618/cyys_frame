# 验证与保存

- 阶段划分、验证频率和结果复用遵循全局《阶段交付与验证规则》。

## 业务流程与检查范围

- 以实际机构内可完成的业务操作和结果查询划分阶段，将相关前后端、权限和数据库改动合并推进。
- 机构数据范围、功能权限、文件访问和审计只检查本阶段受影响的流程与边界。
- 文档和规则修改只检查差异、重复及引用。
- 页面操作按本阶段可用业务流程集中验收；局部检查不足以覆盖风险时才扩大回归。
- 新资源通过实际操作和隔离验证后再开放。

## 数据与环境

- 保留已有测试库数据，不为通过空库检查清库。
- 使用同一数据库测试前停止本地 Docker API。

## 阶段交付与保存

- 阶段收尾在[版本资料](../versions/README.md)中统一更新交付范围、验证结果和待验证项，区分本次执行与复用结果，注明复用来源和适用范围。
- [部署说明](../../deploy/README.md)及受影响的打包、安装材料在阶段收尾统一更新，不为底层小改动单独交付或重复打包。
- 提交前核对差异和已有结果的覆盖范围，不因提交重复执行仍适用的检查。
- 使用本地 Git 提交保存，不另建源码快照。
- 开发规则和必要的模板清单纳入版本管理。
- 本机记录、配置、日志和构建产物继续排除。
